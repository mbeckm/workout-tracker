# Product decisions to review

Picked while porting Family loop into `mobile/`. Trim is usable; these are the calls to walk one by one. Re-checked against `mobile/src` on 2026-09-24.

1. **Log Cancel.** Paper only shows Finish. The app keeps a tertiary **Cancel** on the left so a mid-workout abort is possible without Finish → empty-sets alert. Finish still confirms discard if nothing was logged.

2. **Keyboard docking.** The log footer follows `react-native-keyboard-controller` so wells and Log set ride the system keyboard. The hero stays pinned. Native stack `keyboardHandlingEnabled` is off on Log, New plan, and Prescribe so the whole screen does not jump.

3. **Paywall prices.** Prices come only from StoreKit through the RevenueCat offering (placement = gate reason, else the current offering); nothing is hardcoded. Paper's `$49.99 a year` / `Monthly $5.99` is superseded: 1.0 sells $39.99/yr with a 7-day free trial (annual only) and $6.99/mo, set in App Store Connect. Options render only for packages the offering has (yearly, monthly, and lifetime only if added). While loading, the CTA reads "Loading prices…"; if loading fails it reads "Try again". The CTA says "Start free trial" when the selected yearly plan has an eligible trial, otherwise "Subscribe" ("Buy lifetime" for lifetime). Tapping an option selects it. Auto-renewal terms sit above the CTA; Restore · Terms of Use · Privacy Policy sit in the footer. "Not now" sits top right, always visible. Layout (Sep 2026): one headline with no subheading, benefit rows with an SF Symbol tile, then plan options and the trial timeline, all above the fold on a 6.3" iPhone.

4. **Prescribe edit.** Paper is a read-looking `4 × 8` list. Tap a row to dock SETS / REPS wells (same language as the log) above the keyboard. Values update as you type; empty is allowed until blur, then it clamps to 1–99. Remove is a red caption under the wells.

5. **Add day.** **Add day** appends an empty `Day n` to the plan. Opening an empty day goes straight to the exercise picker, which then lands on the day editor (PE-1). Day rows have a context menu: Rename (the rename prompt, in place; see 56), Duplicate, Move up / down, Remove.

6. **Home / day preview rows.** Read-only (DP-1): each row shows the exercise name and its prescription, and the sheet's one job is Start (or Resume). The exercise sheet route no longer opens from anywhere; it only held media, and 1.0 ships none.

7. **Log strip.** Tap another chip to jump; swipe the stage left or right to move between exercises. Tap the large name for the Exercise sheet (plan, Last time, Best, then Alternatives). Tap the selected chip, or long-press any chip or the name, for the Day sheet. The Day sheet caption says "Drag to reorder": drag a row to move it, tap a row to jump. VoiceOver gets "Show the day" as an action.

8. **In-session swap.** Replaces that slot on the plan and in the current log. Logged sets on that exercise are kept; if none are logged, sets rebuild from the new exercise.

9. **Rest.** Logging a set starts rest, except after the last set of the workout. `Rest` and the clock sit above the wells, with quiet −15 / +15 / Skip on the baseline; tapping the clock also skips. At 0:00 there is one success haptic and the label reads `Go` for two seconds, then rest disappears. Rest keeps running when auto-advance moves to the next exercise, and the Live Activity mirrors the workout on the Lock Screen.

10. **Finished exercise.** When every set is logged, the CTA becomes **Next exercise** (or **Finish workout** when nothing is left), and Last time summarizes the whole last session. Logged sets stay listed above the wells; tapping a well or a set edits that set (**Update set** / Cancel).

11. **Last time.** A single quiet line under `Set n of m`: `Last time 72.5 × 8`, taken from the same set position in the last session (or its last set when this session has more). It stays visible all session; it no longer hides after the first logged set. Units never ride along. The "Previous" residue label is gone. Next-session targets (Pro) will share this caption slot.

12. **History delete.** No ellipsis. Long-press a session for the native context menu with Delete (confirmation follows); VoiceOver gets Delete as an action. Settings → Clear history deletes every completed workout.

13. **Plan activate / delete.** Plans is a 28pt tab title with a `+`. The active plan sits on top as a larger row with a green **Active** caption; other plans are 17pt rows below. The iOS context menu has Use this plan (labelled "(Pro)" for free users) / Rename / Delete. The editor has Use this plan if it isn't active, and Delete plan in red. Remove a day from its context menu or from **Remove day** in the day editor. A plan keeps at least one day.

14. **Onboarding caption.** Paper JSX is 22pt medium for “A plan. Then the gym.” (skill table still says 15). Implemented at 22.

15. **Done.** No checkmark. `Done` 64, then a facts line (day, duration), then per exercise the name plus compressed set lines (`80 × 8 · 8 · 7`) with a PR crown on exercises that set a personal best. Green Done pill. The recap is not capped; it scrolls. Swipe-back is off.

16. **Exercise strip.** Same name as the 34pt title. The strip scrolls horizontally; it does not nickname.

17. **Alternatives.** Same primary muscle from the local catalog, up to three. Copy is equipment, not Paper’s written jokes (“If the bar is taken”).

18. **Rest length.** Paper's rest artboard shows ~1:32. The app sizes rest per exercise: 150s compounds, 60s isolation, 90s unknown strength, 45s mobility, 30s cardio / stretch / timers. An exercise's own `restSeconds` (timers) wins.

19. **Empty weight / prefill.** First session wells start empty (`—`). On a weighted exercise, the first Log set with no weight focuses the weight well once and the CTA reads **Log without weight**; logging then stores `8 reps` instead of `80 × 8`. Logging a set copies its weight and reps into the remaining unlogged sets of that exercise. The next session prefills every set from last time (matching set, or the last set of that exercise if this session has more sets). Wells have −/+ steppers with a selection haptic.

20. **Exercise sheets.** The log's Exercise and Day sheets drag down to dismiss, with a light haptic when they snap. No extra Close link; Paper doesn't have one. There is no Home exercise sheet in 1.0 (see 6).

21. **Done → Pro.** Done opens the paywall after a completed workout when Pro is off and the post-workout paywall has never rendered prices (`postWorkoutPaywallShownAt`). It is recorded only once prices show, so a failed load offers it again next time. After the paywall closes, Done returns to the existing tabs (`dismissTo('/')`). The recap is reached only from Finish; History opens its own session screen.

22. **Unnamed plan discard.** Leaving New plan deletes the draft only if it still has no exercises. An untitled plan with work in it stays.

23. **Paywall from Settings and other gates.** "Not now" just goes back and never counts as the post-workout paywall. Gates (`requirePro`): second plan (Plans `+`), switching plans (context menu and editor), Progress windows beyond 3M on lift and body detail, and body trend charts. Settings → Trim Pro opens the paywall when off, and Manage Subscriptions when on (not for lifetime). Settings also has Restore purchases, Privacy Policy and Terms of Use.

24. **Haptics.** Light impact when a set is logged; success at rest end and at Finish; selection for well steppers, swiping between exercises, and picking a paywall option; light impact when a sheet snaps. Nothing else buzzes.
25. **Units on every number (Sep 2026).** Loads carry the user's unit wherever they appear (`60 kg × 8`) and prescriptions name the reps (`4 × 8 reps`). This replaces the rule that a screen states the unit once (G-9).
26. **Recaps list every set (Sep 2026).** Done and History session detail show each set on its own row with its number, instead of compressing same-weight sets into one line. The crown marks the PR set.
27. **Settings links (Sep 2026).** Rows that leave the app (Contact support, Privacy Policy, Terms of Use) sit in their own group with a trailing ↗ and the link role, so they don't read as settings.
28. **Body check-in (Sep 2026).** Check-in is a native form sheet (`/check-in`) with Cancel and Save in its header. Saving closes it and shows a "Check-in saved" toast. Toasts are only for confirming results that aren't on screen yet.
29. **Product analytics (Sep 2026).** PostHog (EU cloud) via `mobile/src/analytics/analytics.ts`, off until `EXPO_PUBLIC_POSTHOG_KEY` is set. Anonymous: no identify, no person profiles, no GeoIP, no session replay; events carry counts and choices only (onboarding_completed, workout_started, set_logged, workout_completed, check_in_saved, paywall_viewed, purchase_started/finished, restore_finished, plus screens and app lifecycle). PostHog project: EU cloud, product analytics only (no session replay or web analytics), "Discard client IP data" on. The key is in `mobile/.env` and EAS (production, development). The privacy policy names PostHog (26 Sep 2026), and App Privacy lists User ID for App Functionality and Analytics.
30. **App icon (Sep 2026).** "Trim": three rounded bars getting shorter, the shortest green. Layered iOS 26 icon in `mobile/assets/trim.icon` (white fill, ink bars; dark: black fill, white bars), flat fallback `trim-icon.png`, splash marks `trim-splash(-dark).png`. Source: Paper file "Trim Logo". Age rating is 9+ (Health or Wellness Topics: Yes).
31. **Design system v2 (Sep 2026).** `trim-ui` is now the full system: principles, disclosure layers, a closed type ramp (eight sizes, three weights, twelve roles), semantic spacing (`space` in `theme.ts`), one meaning per signal color, shape, icon, motion and haptic tokens, copy rules and component states. What changed: captions are 15 Regular **tertiary** everywhere (`kicker` / `subhead` merged into `caption`; secondary is only for settled content like logged sets); the old 13pt `caption` is now `footnote`; no semibold; one pressed opacity (0.6); disabled is a gray pill, never low opacity; no blue in content; motion must name its purpose (faster, fluid, loveable), a tap shows a reaction within 100ms and its transition finishes within 200ms (280ms only for changes you don't wait on, like a number roll); no helper text or gesture hints (`Drag to reorder`, `Tap to swap`, explainer empty-state captions); sentence case (`Next workout`). The system wins over older Paper artboards. Remaining code debt is listed in `trim-ui` §15.
32. **Control (Sep 2026).** `PRODUCT.md` → Principles → Control: Trim never changes state on the user's behalf. Creating or deleting a plan never changes which plan is active; deleting the active plan leaves none active until the user picks one. Carry-forward after Log set (next set, next unfinished exercise) stays, because it's the visible, expected result of that tap. Code debt: `savePlan` / `updatePlan` in `mobile/src/store/workout-store.ts` still activate a plan when none is active, and `deletePlan` promotes the first remaining plan.
33. **Design system review (Sep 2026).** Kept after review: list rows pad 16, Home has 48 of air before the week, well labels drop tracking and uppercase, and the rest clock is `value` 28 so it never outranks the exercise name. Caption darkness is still open (side-by-side in the design system page).
34. **Design system v2.1 (Sep 2026).** Added to `trim-ui`:
    - **Motion by frequency:** every-set moments get ≤ 150ms or nothing. The 220ms wait before auto-advancing to the next exercise is gone. The next exercise enters from the side you moved toward.
    - **Springs:** no bounce unless a finger threw it (`SPRING.settle` damping 1, `SPRING.fling` 0.8).
    - **Nothing teleports:** a logged set rises from the wells.
    - **Undo over confirm:** recoverable deletes are immediate with an Undo toast; only irreversible ones use an alert. This supersedes the confirm-first parts of 12 and 13.
    - **Gestures:** every gesture action also has a visible standard path (swipe to delete plus a context menu, visible drag handles).
    - **Chart rules** (§11).
    - **The gym setting** (artificial light, arm's length, short frequent visits, music, one hand) and the audience.
    - **Liquid Glass owned fully** for system chrome, never in content.
    - **Automatic token enforcement:** `npm run check` and a GitHub Action ratchet against `mobile/design-tokens-baseline.json`.
35. **Home heading (Sep 2026).** Home drops `Next workout`. The day name becomes the native large title, with one fact under it: the estimated duration (`~55 min`), the most actionable fact for planning the day. The plan name moves a level down (Plans), and the exercise count goes because the list shows it.
36. **Money screens (Sep 2026).** `trim-ui` §12 sets the rules for onboarding, the paywall and Pro gates: every onboarding question changes the product; paywalls only at the four moments, with a headline matching the reason; full StoreKit prices; the trial explained by the timeline; `Not now` always visible; no pressure devices; after purchase, the gated action completes; one measured change at a time.
37. **Words native, numbers big (Sep 2026).** Every page title is the native large title (tab roots, Home's day, plan and session detail). Trim's own large type is kept for numbers and moments (Done, 1RM, wells, rest, week count). `tabTitle` 28 and `display` 40 are deprecated.
38. **Selling and moments (Sep 2026).** Everything is a sale: the product is the salesperson, and the paywall borrows high-converting principles without dark patterns. These are now in `trim-ui` §12: savings stated as a real percentage, real App Store rating as proof only when strong, and buying as a rewarding moment where the lock opens and the action completes. It also defines the moments that get a special feeling (first open, first plan, first workout, first purchase, PR, full week, milestones): once each, after the action, at most 1.2s, built from Trim's own parts.
39. **No middle dots (Sep 2026).** ` · ` separators are a slop marker. Facts are separated by cutting to one, by lanes, by lines, or by natural language. Other slop markers are listed in `trim-ui` §9, and the dot is counted by the token check.
40. **Buying is a moment, not a screen (Marvin, 2026-09-28).** The in-paywall success state (green check, "You're in.", where-each-feature-lives rows, a resume CTA) is replaced by the v2 purchase moment (`trim-ui` §12 rule 17): when Apple confirms, the paywall closes back to where the user was and the gated action completes; once the App Store's sheet is gone and the modal has left, a `Trim Pro is on` toast lands with one success haptic. A paywall restore closes the same way with `Trim Pro restored` (no haptic); a restore that finds nothing stays in place with `No purchases to restore`. Settings → Restore purchases uses the same toasts instead of alerts. A purchase failure shows one red line and the CTA becomes Try again. The paywall footer links (Restore, Terms, Privacy) are separated by air, not dots. `Plan created` keeps its toast but loses the Done haptic (not in the §8 Haptics table).
41. **Plan name in the native title (Sep 2026).** Plan detail's name is the native large title, so it's no longer an inline text field. `Rename plan` (quiet row above Use this plan and Delete plan) opens the system text prompt. A new, unnamed plan opens the same prompt (`Name this plan`) once it has slid in; Cancel leaves it `New plan`, and decision 22's discard still applies.
42. **Home's exercise list is read-only (Marvin, 2026-09-28).** Tapping it no longer opens the day preview sheet: the list already shows every exercise through `n more exercises` / `Show less`, so the sheet only repeated it (feedback F7). Other days' rows still open their preview.
43. **New plan row lights up (Marvin, 2026-09-28).** After a plan is created and isn't active, its Plans row wears the active card's surface once (fade in, hold, dissolve) so the eye finds where it went. Approved as a motion in `trim-ui` §8.
44. **Native titles keep iOS's margin (Marvin, 2026-09-28).** Titles follow the design system and are coherent across the app: every page title is the native large title, which iOS places at its own layout margin (16–20pt), while content keeps the 24 gutter. No screen draws its own title to line up with the gutter, and no content is nudged to meet the title.
45. **No warm-up sets (Marvin, 2026-09-28).** Trim logs working sets only. Warm-up sets, suggested or loggable, stay out: most lifters warm up on their own, and a suggestion line would be helper text on the Log stage. Revisit if beginners ask for it.
46. **Done is a moment (Marvin, 2026-09-28).** Done read as a report ("only loaded with numbers"). It stays `Done` in `hero` plus `Push, 52 min`, and now shows the week this workout moved (`n of m this week` + dots) under it: as the modal finishes sliding in, the new dot fills with the pop and the count rolls up, and a full week gets the bump across all dots. That celebration moves from Home to Done, so it plays once, where the workout lands; Home just shows the new amount. PR crowns land with the pop, a milestone's number rolls up (`9th` → `10th workout`), and each exercise is one line (`4 × 8 reps at 60 kg`, or `4 sets, best 85 kg × 8`), with PR lines in `label` ink. Decision 26 still holds for History's session detail, which lists every set: Done is the moment, detail is the record. No new haptic (Finish already gave the success), no new copy, input never waits.
47. **Starting a workout lights the log (Marvin, 2026-09-28).** Only a fresh Start plays the start moment: `Log set` rides in gray and lights up green as the log lands, with one medium haptic, tappable throughout. Resume, Live Activity links and restored sessions open already lit.
48. **Rest ends in `Go` (Marvin, 2026-09-28).** At 0:00 the rest clock itself becomes a green `Go` with the success haptic, and the Live Activity shows `Go` where its clock was.
49. **Alternatives preview before they swap (Marvin, 2026-09-28).** In the log's exercise sheet an alternative never swaps on tap: its row opens its facts in the same sheet (the sheet morphs), and only `Use this exercise` swaps. `Choose another exercise` opens the full picker and swaps on pick.
50. **Swipes page, taps jump (Marvin, 2026-09-28).** Swiping the log stage pages between exercises 1:1 with neighbours already drawn, committing on a flick; tapping a strip chip jumps with the 8pt nudge.
51. **Weekly streak (Marvin, 2026-09-29).** A full week is one that reaches the plan's goal (its trainable days). Every finished workout counts toward the week, a repeated day too (training Push twice because legs need more recovery is still a workout), capped at the goal. This changes Home's `n of m this week` and Done's dot, which used to count each plan day once; Other days' checks still show which days are done. Home, Done and Weeks now count the same way, so a full green row in Weeks is a streak week. The streak is the full weeks in a row, counted back from this week if it's full, else from last week, so a week still in progress never breaks it. From two weeks up it's a `caption` fact trailing the week dots, `4 weeks in a row`, on Home and on Done. On Done, the workout that completes the week counts it up with the dots as Done lands (it appears there when it reaches 2). No flame, badge, streak screen, freeze, reminder or explainer: Freeletics' Perfect Week Streak (explainer copy plus badge tiers) is the pattern we took the idea from and left the chrome behind. It uses the current goal for past weeks, because past goals aren't stored. Logic: `weekStreak` in `mobile/src/domain/weeks.ts`.

52. **Body deltas stay ink.** A bigger hip or waist isn't progress, so body measurement deltas never turn green; only lift deltas (1RM up) do. Measurement goals (aim up or down per measurement, which would let green follow the goal) are a later product call (Sep 29, 2026).

53. **Chart ranges on top (Marvin, 2026-09-29).** Range chips moved back above the number on lift and body detail: title, chips, hero and delta, chart, sessions. Design system v2.1 had put them under the chart for thumb reach, but Marvin read that as backwards, and the iOS apps Trim sits next to (Health, Fitness, Stocks) put the range first, because it scopes everything under it. Finance apps in the Robinhood family (Cash App, PayPal, Phantom) put it under the chart; we follow iOS instead. Progress is read on the sofa, not mid-set, so reach matters less than reading order. The hero stays directly on its line, and the sessions now follow the line they plot.

54. **Numbers roll and tick (Marvin, 2026-09-29).** Scrubbing's roll and tick is the feel to spread. Picking a chart range now gives one selection haptic on the frame the delta starts rolling and the line starts morphing; the selected chip and a locked one (it opens the paywall) stay quiet. The log gets the same feel: `Set n of m` rolls when a set is logged, undone or picked to edit (a new exercise's page arrives already drawn), and −15 / +15 roll the rest clock to its new time with a selection tick, while the per-second countdown keeps ticking plainly. The well values stay plain: they are text fields, and a roll on the most frequent control in the app would break the every-set motion budget. Added to `trim-ui` §8 Motion and Haptics.

55. **Content meets the title (Marvin, 2026-09-29).** Supersedes 44. Content kept the 24 gutter while the native large title sat at iOS's 16–20 margin, and Marvin read the 8pt step as misalignment twice: the `~55 min` fact floated off the title on Home, and Plans' heading and rows didn't share an edge. Under a native large title, content now sits on the title's own edge (`space.margin`, iOS's layout margin: 16, or 20 from 414pt wide), like Apple's own apps; screens without a native title keep the 24 gutter. The title block (title + one fact line) is followed by `section` (32) to the first thing you see, and no section below starts further from its neighbour than the first one does from the title (History's months had 48 against the title's ~20). Rules in `trim-ui` §4 Under a large title.

56. **One rename pattern: the system prompt (sprint 2026-09-29, revised the same day).** The plan was renamed in the system prompt while a day was renamed in an inline title field, two patterns for one job. Both now use the prompt (`navigation/rename-prompt.ts`), from the same two places: `Rename` in the row's context menu (a plan on Plans, a day on plan detail; a day no longer pushes its editor just to change its name) and the editor's own `Rename plan` / `Rename day` row. The day editor's title became the native large title like every other page, so no title is a text field. Inline editing was weighed and not built: the native large title can't be edited, drawing our own on two screens would undo "words are native", and list apps with large titles (Rodeo, Shop, Hypelist, Edits; Apple's Notes folders and Safari tab groups) rename in a prompt or sheet, while in-place title editing belongs to document apps (Craft, Obsidian) where the title is part of the body. The earlier fix still holds: both buttons are gray (a preferred `Save` would be the only blue in Trim), Return saves, the prompt takes Trim's own light/dark, and an empty or unchanged name keeps the old one, so a plan or a day is never blank. A new plan still asks `Name this plan` once. Rules in `trim-ui` §10 Rename.

57. **A glyph earns its place by making Trim faster to glance (sprint 2026-09-29, from Marvin's feedback; supersedes the first 57, "icons mark commands, not content").** Settings looked better with its glyphs, but the rule "commands and settings lead with a glyph; content never does" left the rest of Trim leaning on words, and glancing is the whole job between sets. The rule is now one question: does the eye find or read this faster with the glyph than with the word? A glyph names a command or setting, carries a state (done, PR, locked), or stands in for the name of a fact that comes back across screens, leading its number: `timer` for how long, `clock.arrow.circlepath` for last time, `target` for the Pro target, the crown for a PR count. It never names content, never decorates a title, caption, CTA or empty state, and never repeats down a list where the lane already says what the fact is. Applied: the log's line under `Set n of m` drops the words `Last time` (and on Pro, `Target`), so the eye lands on the number and the two numbers on the Pro line are told apart by shape; History's PR pill drops `PRs` (crown + count); session detail's amount line becomes `timer 52 min`, `14 sets`, crown + PR count; Done and the day preview lead their duration with `timer`. Research (Strong, Hevy, Fitbod, Apple Fitness, Gentler Streak, Oura; Family isn't on Mobbin): Strong's history card is the model, a clock, a weight and a trophy telling three numbers apart with no labels; Hevy and Fitbod label the same numbers with words or uppercase headers and read slower; Garmin, Bevel and Gentler Streak put an activity-type glyph on every row, which only helps when there are types to tell apart. Kept from the first 57: Settings' and the editors' row glyphs, no glyph per content row, and no glyph above an empty state (History's `clock` over `No workouts yet` read as a third heading). Rejected: a `timer` on every History row and a `clock.arrow.circlepath` on every Progress row (one shape repeated down a list), glyphs on section captions and the week's `this week`, a glyph for `Rest` (one short word over a 28pt clock that already reads as time), and a flame for the streak (51). Rule and symbol table in `trim-ui` §7.

58. **Home's duration sits under Start (sprint 2026-09-29, G3; awaiting Marvin's OK).** Supersedes the fact line of 35. Marvin asked whether `~40 min` is really the second most important thing on Home, sitting right under the day's name. It isn't: the day's name says what, the exercise list says what's in it, and Start is the one action; the duration is what that action costs, so it now sits under Start as a centered `caption` (`related` apart), like the price note under a paywall CTA or the App Store's note beside Get. Mid-workout the same line says `Started 14:02` under Resume. The title block on Home is the native large title alone, and the list starts `section` under the bar. An empty day loses `No exercises yet`: `Add exercises` already says it. Research: Hevy's routine cards show no duration at all; Apple Fitness+ leads its meta line with it right above `Let's Go`; Fitbod and Future put stats as a header inside the workout block. Four placements were compared in Paper (page `Home duration (2026-09-29)`): as before, as the card's header line, as the card's footer, and under Start. Inside the card, a lone `caption` has no name to belong to (every other line in the card is a name + its meta), so it read as an orphaned meta at the top and as clutter under `n more exercises` at the bottom.
59. **One grabber on every sheet (sprint 2026-09-29, G4; awaiting Marvin's OK).** iOS draws a native sheet's grabber 5pt from the edge, tight under the floating sheet's large corners, while Trim's custom log sheets drew theirs 14pt down, so the handle sat differently from sheet to sheet. Every sheet now draws Trim's own grabber (`PaperGrabber`, 36×5, `systemGray4`) 12pt (`GRABBER_INSET`) from its top edge: native `formSheet`s hide the system grabber (`sheetGrabberVisible: false`) and overlay ours without moving their content; the log's custom sheets carry it in flow, `inset` above their title. Drag-to-dismiss and detents stay native. Rule in `trim-ui` §10 Sheets.
60. **Home leads with your numbers (exploration, Marvin, 2026-09-29; superseded by 61).** Home read as polished but bland, "like a prototype": it showed the plan, not the person. An exploration (Paper, page "Alive (2026-09-29)") tried four directions. Per-day colors and colored cards were rejected: color without a job reads as childish and like Apple Wallet. "Your numbers" was kept and is now built as a second Home (`mobile/src/screens/workout-tab-numbers.tsx`), with the classic Home unchanged (`workout-tab.tsx`, one line to switch back in the Workout route). What changes:
    - **Under the title**, when this day was last done and how long it took (`Last time Thu 24, 48 min`); the estimate (`~50 min`) only before the first time.
    - **A number to beat** for the day's first weighted lift, in `hero`. Pro: today's target, and how much it goes up in green at `title` size (`Flat Barbell Bench Press today`, `62.5 kg`, `↑ 2.5 kg more than last time`). Free: last time's heaviest set (`… last time`, `60 kg`, `6 reps`). Free users get no arrows, so the ↑ stays a quiet reason to go Pro, never a nag.
    - **Every exercise shows your load** in the trailing lane at `title` size, with a green ↑ where the Pro target raises it. The gray list surface goes; rows sit on the page with hairlines. From the larger text sizes up, the load stacks under the name.
    - **The week as seven days**, Monday first: green with a check on each day trained, today as an ink ring, every other day grey (missed days aren't marked). `n of m this week` and the streak stay above it, and the block still opens Weeks.
    - **Green gets a second meaning next to done: up.** Trim's one brand color says "you made progress": checks, a heavier target, a full week.
    Its code was replaced by Home v3 (61): `screens/home.tsx` is the Home, and `workout-tab-numbers.tsx` stays in the repo unused. Decide on device before merging. If it stays, `trim-ui` §13 Home and "Home week details" get rewritten, and the classic Home goes. Dev check: `EXPO_PUBLIC_HOME_DEMO=pro` or `=free` loads a never-saved four-day plan with three weeks of history (`mobile/src/store/home-demo.ts`).
61. **Home v3: the moment decides the screen (Marvin, 2026-09-29; built: Home in `screens/home.tsx`, Done v2 in `screens/workout-complete.tsx`, the week moment on Home after Done, and change in ink on Progress).** Supersedes 60's layout, 58's duration under Start, the Other days list of 35/42, and the "no flame" of 51 and 57. Designed over four Paper rounds (page `Your numbers (2026-09-29)`, the agreed row is V4) from one question: why does someone open Home? To start a workout, three to six times a week. Logging lives in the log, stats in Progress, plan editing (rare) in Plans, so Home keeps only what helps you start or makes you want to.
    - **Layout:** the streak on top (🔥 `3 weeks`, no `in a row`), the week as seven day circles (no `n of m`: the circles are the count), then `Next workout` as day chips over the selected day's exercises as single-line rows with your load (up to 8 fit), and ink `Start Upper` at the thumb. No native large title, no weekday title ("nobody cares that it's Tuesday"), no last-time date or duration, no Other days list: the chips replace it and switching days is visible (a ⌄ on the title wasn't discoverable). Chips page with a swipe.
    - **States:** training day, just trained (what changed, the crown on PRs, the next day as a quiet gray pill), week complete (the flame lights, `↑ 9 lifts went up`, 👑 `2 new records`, and another workout stays one ink tap away), mid-workout (Resume).
    - **Color, one job each:** green = completeness only (done / go), never improvement; yellow = record; orange = streak secured (the flame, gray until the week's goal is reached, the only orange in Trim); change is ink (↑ ↓ `same`). Green was carrying both done and up, and "Just trained" had five green shapes. Ordinary progress is too common for a color; motion makes an ↑ feel earned. This also turns Progress's and lift detail's up-delta ink (52 already kept body deltas ink).
    - **Rejected along the way:** per-day identity colors and colored day cards (color without a job read childish and like Apple Wallet), a hero number to beat (it repeated the first row), the weekday as title, `1 of 4 this week` next to the circles, a hero-size streak on week complete (celebrate by state and motion, not size), a yellow weight for PRs (unreadable).

62. **Progress v3: calm, goals first (Marvin, 2026-09-29; built in `screens/progress-tab.tsx`, sparklines fixed at 30 days).** Paper page `Done + Progress v3`, artboard `Progress A2`. Progress is goals, lifts and body, nothing else. Goals: capped at 3 (a goal is a focus; a 4th means swapping one out), shown first with a green track, and a goal's lift is promoted out of the list so every lift appears once; tapping one opens its detail with the goal as a target line. Lifts and Body: one line each, name, sparkline, value, on fixed lanes. The sparklines cover 30 days, sensible for most lifters, with 90 days as a setting; no range chips on the page. Rejected on the way: an aggregated month summary (September counts), a page-wide range picker with a headline ("10 of 12 lifts went up"), goals inside the lift rows (read as thrown together), a hero chart and a powerlifting total (too loud; a total may come back as a goal type). The change per lift and the counts felt like too much improvement; the sparkline carries the direction. Lift detail keeps its own range chips, and the range chosen there carries over between lifts.
63. **Goals: unlimited, 3 pinned; lift detail v5 (Marvin, 2026-09-29; built: goals, Progress, the goal sheet, lift detail v5 and Done's goal row).** Amends 62's cap of 3.
